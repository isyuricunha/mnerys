# Architecture Documentation

The [Mnerys roadmap](../ROADMAP.md) defines the **target** Python Agent Core, authoritative Gateway and shared CLI/TUI/Web interfaces. The [M1 exit review](M1_EXIT_REVIEW.md) closes the **audit-and-contract-design scope only** and preserves all operational Gateway, multi-transport and durability gates for the [M2 implementation plan](M2_GATEWAY_IMPLEMENTATION_PLAN.md). The M1 audit documents inherited behavior and **proposes** a shared contract. Opt-in process-local SSE replay cursors, the first internal TurnService extraction, typed Gateway session admission, a read-only session ownership lookup port, account privilege-denial preparation and shared message persistence serialization are implemented. Experimental incarnation-fenced background delivery and cache reconciliation are tested **without production activation**. The inherited session append/cache failure path and agent metadata tool double-write issue have targeted compatibility fixes. The first [M2.1 authority extraction](M2_GATEWAY_IMPLEMENTATION_PLAN.md#m21--finish-the-internal-authority-and-turn-boundary) now uses `GatewayTurns.build_authority` with a verified admission proof to construct the Web stream's initial request authority, without independent owner/session inputs and with delegated-credential denial retained. Exact-approval continuation authority and decision validation/consumption now pass through this facade. The original approval store retains destructive single-use semantics, the Web adapter retains HTTP credential checks and card reconciliation, and the dispatcher still claims sealed operations. Owner-scoped foreground fallback policy, candidate/descriptor selection and per-candidate non-persistent context shaping now also pass through the same admitted facade for both non-stream and streaming Chat. Final prompt selection now also checks context ownership, preserves exact-approval continuation history and guards internal-tool content as untrusted data through `GatewayTurns`. The [shared context builder](../../routes/chat_helpers.py) now has an HTTP compatibility wrapper and a request-independent `build_chat_context_core` accepting a trusted owner and a message-event callback; the [admission guard](../../src/gateway_context_admission.py) binds both Web endpoints to their issued session and verifies the HTTP principal before preprocessing. An [M2.1 context-port contract](M2_CONTEXT_SERVICE_PORTS.md) now defines injectable operations for the existing preset, preprocessing, preference, attachment, memory/RAG, message-write, model identity, YouTube attribution, clock, history and context-window services. The legacy adapter delegates to the original providers without duplicating their storage or engine. Remaining helpers, storage, model execution and actual context-state commits still depend on inherited components. These seams reuse the inherited agent loop and run manager; a standalone authenticated Gateway, durable events and Mnerys CLI/TUI are not implemented yet.
